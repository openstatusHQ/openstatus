You can now hold your monitors to a monthly uptime target. Open [**Reportings > Monitors**](https://app.openstatus.dev/reportings/monitors), name a reporting, pick a target like `99.9%` and the monitors it covers.

The reporting page shows each monitor against the last 12 or 24 months, green when it met the target and red when it missed, plus the running month as provisional. Cards show the target, the lowest monitor this month and how many of the last twelve months had a miss.

- **Judged per monitor, per month.** There is no blended figure across monitors.
- **Runs, not requests.** Each scheduled check gets one verdict across its cloud regions: it fails only when at least half of the reporting regions failed, so one bad region out of three is not an outage.
- **Sealed months.** After a three-day correction window, each month is sealed with the target that applied, and later edits never rewrite it.
- **Strict mode.** Turn on **Count slow responses as downtime** to count checks over the monitor's degraded threshold as down.
- **Maintenance.** By default a monitor is not checked during a status page maintenance on a component it is linked to, so that time is not counted at all. A monitor can now keep checking without alerting, so a maintenance that overruns counts against its uptime.
- **CSV export.** Download a range of months with the run counts, uptime, target and whether each month is sealed. The file states the method, ready to send to a customer.
- **Email on a miss.** Workspace owners get an email when a sealed month misses its target.

Reportings are included in the Pro and Scale plans. Read the [monitor reporting reference](/docs/reference/monitor-reporting) for the exact method.
